# RC1 Marketplace read states

`getMarketplaceListingsResult()` adds a ready/unavailable result without changing the existing `getMarketplaceListingsData(): Promise<Product[]>` contract. The new path never imports or substitutes static demo products. Empty successful reads return ready with an empty array; missing configuration, network/timeout failure, unsuccessful read, malformed response, and failed submission-lifecycle lookup return unavailable.

The public Marketplace and listing-detail pages use the result-bearing loader and also respect failed Farmer/Supplier reads. They display truthful unavailable copy instead of treating those failures as zero results or a missing listing. Detail metadata marks temporary read failure noindex. A genuine successful read with no eligible matching listing still follows the existing not-found path. Publication, seller matching, custom-unit review, deduplication and ordering remain unchanged.

Validation: `node tests/rc1-marketplace-availability.cjs` passed. All reads were mocked locally. Tests cover configuration, network, HTTP status, invalid JSON/row, empty/nonempty data, secondary lifecycle lookup failure/success, legacy array return type, rendered browse/detail unavailable states, metadata noindex and actual not-found distinction. No Supabase requests or database writes occurred.

Synthetic-marker audit: existing demo, seed, mock, sample and placeholder exclusions remain. RC1 also excludes exact `recordSource` tags `synthetic`, `preview-fixture`, `preview_fixture`, `test-fixture` and `test_fixture`, plus IDs beginning `p09-preview-`, `p09-preview_` or `p09-preview:`. Checks verify that ordinary preview wording in a name or an unmarked record does not trigger this extension. This narrowly implements the founder's fixture exclusion; publication and other lifecycle decisions are unchanged. The listing mapper reads `record_source` rather than a generic `source` field. No live rows were inspected or changed, so no claim is made that marked rows currently exist.
